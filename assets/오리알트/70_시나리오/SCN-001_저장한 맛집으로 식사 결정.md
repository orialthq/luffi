# 한 문장 정의

사용자가 과거에 캡처해둔 맛집 중 이번 식사 상황에 맞는 한 곳을 결정하고 실제 방문까지 이어간다.

# 사용자 문제

사용자는 SNS에서 가고 싶은 맛집을 자주 캡처하지만, 막상 식당을 정해야 할 때는 캡처를 다시 찾지 못하거나 처음부터 검색한다.

그 결과 저장한 정보는 쌓이지만 실제 방문으로 이어지지 않는다.

# 시작 조건

- 사용자에게 맛집 캡처가 5장 이상 있다.
- 가까운 시일 내 식사 장소를 정해야 한다.
- 사용자가 식사할 지역과 시간을 입력할 수 있다.

# 사용자 흐름

1. 사용자가 최근 맛집 캡처 5~10장을 한 번에 선택한다.
2. 서비스가 캡처에서 식당명과 지점을 식별한다.
3. 사용자가 식사 상황을 한 문장으로 입력한다.
4. 서비스가 이용할 수 없는 식당을 제외한다.
5. 가장 적합한 한 곳과 대안 두 곳을 제시한다.
6. 사용자가 지도·길찾기·예약·공유 중 하나를 실행한다.
7. 식사 이후 실제로 어디를 방문했는지 한 번의 탭으로 확인한다.
8. 방문 결과를 다음 식사 결정에 반영한다.

# 입력 예시

> 금요일 저녁 7시, 성수, 2명

# 출력 예시

> 저장했던 8곳 중 금요일 7시에 성수에서 갈 수 있는 곳은 3곳이에요.  
> 가장 먼저 추천하는 곳은 ‘성수다락 성수점’이에요.

- 현재 조건에서 이용 가능
- 저장한 곳 중 이동 시간이 가장 짧음
- 사용자가 비슷한 메뉴를 반복해서 저장함
- 다른 후보 두 곳도 확인 가능

# 예외 처리

## 식당 지점을 특정하지 못함

가능한 지점 후보를 보여주고 사용자에게 한 번만 확인받는다.

## 조건에 맞는 식당이 없음

웹에서 새로운 식당을 임의로 채우지 않는다.

> 저장한 곳 중 이번 조건에 맞는 식당은 아직 없어요.

라고 명확하게 알려준다.

## 영업 여부를 확인하지 못함

이용 가능한 것처럼 추천하지 않고 확인이 필요하다고 표시한다.

## 사용자가 결과에 응답하지 않음

방문 여부를 `unknown`으로 두며 방문했다고 추정하지 않는다.

# 첫날 제공 가치

사용자는 취향 학습을 기다리지 않아도 다음 결과를 즉시 받는다.

> 캡처 8장에서 식당 6곳을 확인했어요.  
> 이번 금요일 성수에서 갈 수 있는 곳은 3곳이에요.

# MVP 필수 기능

- 여러 맛집 캡처 선택
- 이미지에서 식당 후보 추출
- 정확한 식당 지점 확인
- 식사 상황 한 문장 입력
- 한 곳과 대안 두 곳 제시
- 지도·길찾기·예약·공유 연결
- 방문 결과 한 번의 탭으로 확인

# MVP에서 제외

- 백그라운드 위치 추적
- 근처 맛집 자동 알림
- 광범위한 신규 맛집 웹 검색
- 폴더와 태그 중심 정리
- 친구의 앱 가입을 요구하는 공동 기능
- 자동 예약 완료
- 강화학습 기반 자동 최적화

# 핵심 측정 지표

- 맛집 캡처 5장 이상 등록 완료율
- 식당 및 정확한 지점 식별 정확도
- 식사 상황에 맞는 후보가 존재하는 비율
- 지도·길찾기·예약·공유 실행률
- 저장했던 식당의 확인된 방문률
- 두 번째 식사 결정 재사용률
- 새로운 캡처 추가율

# 확인할 핵심 가설

상황에 맞는 한 곳을 먼저 제안하면 단순 저장 목록보다 식당 결정 시간이 30% 이상 줄고, 저장한 식당의 실제 방문률이 15%p 이상 높아진다.
