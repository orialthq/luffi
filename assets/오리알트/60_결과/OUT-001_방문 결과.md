# 정의

추천과 행동 이후 사용자가 실제로 어디를 방문했는지 기록한 결과다.

클릭이나 길찾기 시작이 아니라, 서비스가 사용자의 현실 행동을 바꿨는지 확인하기 위한 데이터다.

# 기록할 결과

- 가장 먼저 추천한 식당을 방문함
- 대안으로 제시한 식당을 방문함
- 저장했던 다른 식당을 방문함
- 저장하지 않았던 다른 식당을 방문함
- 식사 약속이 취소됨
- 결과를 확인하지 못함

# MVP에서 확인하는 방식

예상 식사 시간이 지난 뒤 한 번만 묻는다.

> 결국 어디로 갔어요?

- 첫 번째 추천
- 다른 추천 후보
- 다른 곳
- 약속 취소
- 답하지 않기

사용자가 한 번의 탭으로 답할 수 있어야 한다.

# 증거의 강도

## 확인됨

사용자가 직접 방문했다고 응답한 경우.

## 추정됨

예약 완료 정보나 선택적인 위치 신호가 방문 가능성을 뒷받침하는 경우.

## 알 수 없음

지도·길찾기·예약 화면만 열었거나 사용자가 응답하지 않은 경우.

위치가 가까웠다는 사실만으로 방문 완료라고 확정하지 않는다.

# 함께 받을 수 있는 피드백

- 추천이 상황에 잘 맞았는지
- 다시 가고 싶은지
- 선택하지 않은 이유
- 정보가 잘못되었는지

처음에는 방문 여부만 받고, 추가 피드백은 선택 사항으로 둔다.

# 학습에 사용하는 원칙

- 한 번 선택하지 않았다고 싫어하는 장소로 단정하지 않는다.
- 반복된 선택과 거절을 구분해 누적한다.
- 저장 횟수보다 실제 선택과 방문에 더 높은 가중치를 둔다.
- 잘못된 장소 식별이나 영업 정보 오류는 취향 신호로 사용하지 않는다.

# MVP에서의 역할

캡처가 실제 방문으로 이어지는지 측정하고, 다음 식사 결정의 정확도를 높이는 피드백 루프를 만든다.

# 확인할 가설

상황에 맞는 한 곳을 먼저 제안하면 단순한 저장 목록을 보여줄 때보다 저장한 식당의 실제 방문률이 15%p 이상 높아진다.
