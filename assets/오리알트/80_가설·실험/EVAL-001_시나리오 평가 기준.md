# 목적

100개 이상의 사용자 시나리오를 같은 기준으로 비교하고, 어떤 시나리오부터 검증할지 결정한다.

점수는 사실이 아니라 현재 가설이다. 인터뷰와 실제 행동 데이터가 생길 때마다 수정한다.

# 평가 항목

모든 항목은 1점부터 5점까지 평가하며, 높을수록 MVP에 유리하다.

## value_score

사용자에게 생기는 실질적인 이득의 크기.

- 1점: 있으면 조금 편리함
- 3점: 시간·돈·결정 부담을 줄임
- 5점: 분명한 손실을 막거나 중요한 결과를 만듦

## frequency_score

해당 상황이 발생하는 빈도.

- 1점: 1년에 몇 번
- 3점: 한 달에 몇 번
- 5점: 매일 또는 매주 여러 번

## timing_score

정확한 순간에 제공했을 때 가치가 얼마나 커지는지.

- 1점: 언제 봐도 차이가 없음
- 3점: 특정 시점에 보면 더 유용함
- 5점: 그 순간을 놓치면 가치나 기회가 사라짐

## data_feasibility_score

필요한 데이터를 현실적으로 얻을 수 있는지.

- 1점: 플랫폼 제약이나 민감한 권한 때문에 사실상 어려움
- 3점: 사용자의 수동 입력이나 확인이 필요함
- 5점: 낮은 권한 비용으로 안정적으로 얻을 수 있음

## outcome_measurability_score

추천 이후 실제 결과를 확인할 수 있는지.

- 1점: 결과를 거의 알 수 없음
- 3점: 사용자 확인이 필요함
- 5점: 실제 행동 결과가 자동 또는 명확하게 돌아옴

## low_friction_score

사용자가 정보를 맡기고 서비스를 이용하기 쉬운지.

- 1점: 복잡한 연동·다수 권한·긴 입력이 필요함
- 3점: 최초 설정이나 일부 수동 입력이 필요함
- 5점: 한두 번의 탭으로 바로 시작할 수 있음

## build_feasibility_score

작은 팀이 짧은 시간 안에 MVP를 만들 수 있는지.

- 1점: 외부 제휴·대규모 데이터·고난도 모델이 필요함
- 3점: 일부 수작업이나 외부 API가 필요함
- 5점: 현재 기술과 데이터로 바로 실험할 수 있음

## learning_loop_score

사용할수록 다음 판단을 개선할 실제 결과 데이터가 쌓이는지.

- 1점: 사용 후 새로운 정보가 거의 생기지 않음
- 3점: 선택·거절 같은 간접 신호가 생김
- 5점: 예측과 실제 결과를 반복해서 비교할 수 있음

## differentiation_score

기존 서비스와 다른 완결된 가치를 제공하는지.

- 1점: 기존 앱의 작은 기능으로 대체 가능
- 3점: 흐름은 다르지만 쉽게 복제될 수 있음
- 5점: 독자적인 데이터·워크플로·학습 구조가 생김

# 우선순위 점수

가중치는 다음과 같이 적용한다.

- `value_score × 2`
- `frequency_score`
- `timing_score`
- `data_feasibility_score × 2`
- `outcome_measurability_score × 2`
- `low_friction_score`
- `build_feasibility_score`
- `learning_loop_score × 2`
- `differentiation_score`

최대 점수는 65점이며, 100점 기준으로 환산한다.

계산식:

`priority_score = 가중 합계 ÷ 65 × 100`

# 증거 수준

점수와 별도로 `evidence_level`을 기록한다.

1. `assumption` — 팀의 생각만 있음
2. `interview` — 사용자 인터뷰에서 확인
3. `concierge` — 사람이 대신 수행한 실험
4. `prototype` — 동작하는 MVP로 확인
5. `observed-behavior` — 실제 사용 행동으로 확인
6. `repeated-evidence` — 여러 번 반복해서 같은 결과 확인

높은 점수라도 `assumption` 단계라면 검증되지 않은 가설이다.

# MVP 보류 조건

다음 중 하나에 해당하면 점수가 높아도 바로 개발하지 않는다.

- `value_score`가 2점 이하
- `data_feasibility_score`가 2점 이하
- `outcome_measurability_score`가 2점 이하
- 합법적이고 신뢰할 수 있는 데이터 수집 경로가 없음
- 첫 사용에서 가치를 제공할 방법이 없음

# 사용 원칙

- 점수는 아이디어를 정답처럼 결정하지 않는다.
- 점수는 먼저 검증할 가설을 고르는 데만 사용한다.
- 실제 증거가 생기면 점수와 근거를 함께 갱신한다.
- 종합점수가 같다면 사용자 가치와 데이터 가능성이 높은 쪽을 우선한다.
