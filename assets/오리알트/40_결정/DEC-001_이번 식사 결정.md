# 정의

사용자가 저장한 식당 지점과 이번 식사 상황을 결합해, 이번에 실제로 갈 한 곳을 먼저 제안하는 결정이다.

# 입력

- 사용자가 캡처했던 식당 지점
- 이번 식사의 지역과 시간
- 필요한 경우 인원·예산·목적·제약 조건

# 판단 단계

1. 정확한 식당 지점인지 확인한다.
2. 지역과 이동 가능 범위에 맞지 않는 곳을 제외한다.
3. 해당 시간에 영업하지 않는 곳을 제외한다.
4. 예산·인원·알레르기 등 명확한 제약에 맞지 않는 곳을 제외한다.
5. 남은 후보를 저장 근거와 상황 적합도로 비교한다.
6. 가장 적합한 한 곳과 대안 두 곳까지 제시한다.

# 우선순위 신호

- 같은 식당을 반복해서 캡처했는지
- 최근에 저장했는지
- 캡처에 사용자가 원하는 메뉴가 보이는지
- 이번 식사 지역과 이동 시간이 가까운지
- 이번 시간에 실제로 이용할 수 있는지
- 사용자가 과거에 선택하거나 거절한 패턴과 맞는지

# 출력

- 가장 먼저 제안할 식당 한 곳
- 대안 식당 최대 두 곳
- 지금 이 식당을 제안한 이유
- 지도·길찾기·예약·공유로 이어지는 행동

# 결정하지 않는 조건

- 식당 지점을 정확히 특정하지 못한 경우
- 영업 여부나 위치가 불확실한 경우
- 조건에 맞는 후보가 없는 경우

후보가 없으면 웹에서 새로운 맛집을 채워 넣지 않고, 저장한 곳 중에는 적합한 곳이 없다고 알려준다.

# MVP에서의 역할

저장된 맛집 정보를 다시 보여주는 데서 끝내지 않고, 실제 식사 결정으로 전환한다.

# 확인할 가설

사용자는 전체 저장 목록보다 상황에 맞는 한 곳과 대안 두 곳을 받았을 때 더 빠르게 식당을 결정하고 실제 행동으로 이어간다.
