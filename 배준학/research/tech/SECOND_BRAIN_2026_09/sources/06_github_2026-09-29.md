## Luffi: GitHub research on memory, knowledge-graph and retrieval repos beyond the known list (as of 2026-09-29)

I ran about 45 search queries and about 110 repo, README, license and release lookups through the `gh` API. Every star count, license, language and push date below comes from the API today. Where GitHub shows a license as NOASSERTION, I read the LICENSE file itself.

One thing I couldn't do: the stargazer-history endpoint returned 404 for every repo. So my star-farming flags are based on ratios (stars vs. watchers vs. contributors vs. commits since July), not on star timelines.

**Brief status of the repos you already know:**
- **Version bumps:** Graphiti v0.30.2, Cognee v1.6.1, Mem0 v2.2.1, Hindsight v0.10.1 (41k★), MemOS v2.0.34, LightRAG v1.5.7.
- **Graphiti security:** a high-severity Cypher-injection advisory (CVE-2026-32247) was published on 2026-03-11.
- **License changes:**
  - **OpenViking** switched from Apache to AGPL-3.0 on 2026-03-30.
  - **Honcho** v3.2.1 is AGPL.
  - **Mastra** has its `ee/` folders under a separate license; the rest is Apache.
- **Stale:** Memobase (no push since Jan 2026) and A-MEM (no push since Dec 2025).

Legend: ✅ permissive, ⚠️ conditional (copyleft or restricted).

### 1. Memory / knowledge-graph engines
- **[smaramwbc/statewave](https://github.com/smaramwbc/statewave)** · 355★ · Apache ✅ · Python, plus a TypeScript SDK (statewave-ts) · pushed 09-26
  - **Novel:** turns each subject's raw events into typed memories once, then builds token-bounded context bundles. Every bundle carries content-hashed provenance receipts you can replay. Runs on Postgres + pgvector.
  - **Fit: HIGH.** Postgres-native, strict provenance, deterministic context for TaskBoards.
- **[Zleap-AI/SAG](https://github.com/Zleap-AI/SAG)** · 2.5k★ · MIT ✅ · Python · 09-29
  - **Novel:** indexes each chunk as one event linked to its entities. Cross-entity links are built at query time with SQL joins, so there is no global entity-merge step at ingest (arXiv 2606.15971).
  - **Fit: HIGH.** Avoids silent merges by design and has a stated path to Postgres/pgvector.
- **[atomicstrata/atomicmemory](https://github.com/atomicstrata/atomicmemory)** · 433★ · Apache ✅ (LICENSE file) · TypeScript core · 09-28
  - **Novel:** handles corrections explicitly (supersede, clarify, delete, retain), with a TypeScript SDK over Postgres/pgvector.
  - **Fit: HIGH on stack.** Young project with 3 contributors.
- **[joshuaswarren/remnic](https://github.com/joshuaswarren/remnic)** · 211★ · MIT ✅ · TypeScript · 09-28
  - **Novel:** corrections need human approval and are applied as append-only supersessions. Each search result shows its provenance. About 2.3k commits since July.
  - **Fit: MED.** Stores memory as files; borrow its correction contract.
- **[memoweft/memoweft](https://github.com/memoweft/memoweft)** · 4★ · MIT ✅ · TypeScript · 09-29
  - **Novel:** keeps "user said", "observed", "model inferred" and "conflicted" as separate record types. Confidence comes from rules, not the model.
  - **Fit: HIGH on concept** (tiny; watch it).
- **[a-finance-bro/wend-core](https://github.com/a-finance-bro/wend-core)** · 8★ · AGPL ⚠️ · TypeScript + Postgres/pgvector · 09-09
  - **Novel:** every fact links to a sources row, and agent writes wait in a queue until a person approves them. Also has an aliases table, a conflicts table and name-match tiers ("a partial hit is never an identity").
  - **Fit: study the design only** (AGPL).
- **[bigai-nlco/bcg](https://github.com/bigai-nlco/bcg)** · 218★ · MIT ✅ · TypeScript · 09-03
  - **Novel:** a "belief" graph that tracks confidence, validity window and evidence for each fact, and revises beliefs when outcomes prove them wrong.
  - **Fit: MED.** A model for the confidence of inferred intents.
- **[semantica-agi/semantica](https://github.com/semantica-agi/semantica)** · 13.5k★ · MIT ✅ · Python · 09-28
  - **Novel:** attaches W3C PROV-O provenance to every fact, flags conflicts, dedups with blocking, and can store the graph in Apache AGE.
  - **Fit: MED.** Enterprise-heavy.
- **[neo4j-labs/agent-memory](https://github.com/neo4j-labs/agent-memory)** · 571★ · Apache ✅ · Python · 09-28
  - **Novel:** extracts entities in stages (spaCy, then GLiNER, then LLM) and relations with GLiREL.
  - **Fit: LOW–MED.** Neo4j only.
- **[FlowElement-xinliuyuansu/m_flow](https://github.com/FlowElement-xinliuyuansu/m_flow)** · 4.5k★ · Apache ✅ · Python · 09-01
  - **Novel:** a four-level Episode → Facet → FacetPoint → Entity graph, with retrieval scored along evidence paths.
  - **Fit: MED as an idea.** Only 1 commit since July.

### 3. Entity resolution
- **[moj-analytical-services/splink](https://github.com/moj-analytical-services/splink)** · 2.4k★ · MIT ✅ · Python · 09-28
  - **Novel:** unsupervised Fellegi-Sunter match weights that explain each match, with a Postgres backend.
  - **Fit: HIGH** as a batch sidecar: score matches, then route borderline pairs to user review instead of auto-merging.
- **[fastino-ai/GLiNER2](https://github.com/fastino-ai/GLiNER2)** · 2.2k★ · Apache ✅ · Python · 09-24
  - **Novel:** named entities, relations and classification from one schema in a single CPU pass. Ports exist: gliner-onnx.js (TypeScript), gline-rs, Gliner2Swift.
  - **Fit: MED–HIGH** as a cheap pass before the LLM. Korean quality is unverified.
- **[xoai/sage-wiki](https://github.com/xoai/sage-wiki)** · 620★ · MIT ✅ · Go · 09-28
  - **Novel:** entity-resolution proposals are reviewed by people. Each edge carries its source and a confidence, and query answers are held back until verified. Postgres backend.
  - **Fit: MED–HIGH** as a design reference.
- **[Knowledgator/GLinker](https://github.com/Knowledgator/GLinker)** · 156★ · Apache ✅ · Python · 07-20
  - **Novel:** zero-shot entity linking: GLiNER recognition, candidate lookup (Redis → Elasticsearch → Postgres), then disambiguation.
  - **Fit: MED.**
- **[benseverndev-oss/goldenmatch](https://github.com/benseverndev-oss/goldenmatch)** · 132★ · MIT ✅
  - **Novel:** zero-config dedupe that merges duplicates into one "golden" record.
  - **Fit: LOW.** Auto-merging conflicts with your no-silent-merge rule.
- **Gap:** I found no mature TypeScript entity-resolution library; searches returned only toy repos.

### Top 10 picks
1. **pg_textsearch with Kiwi-WASM:** morphemes → `tsvector('simple')` → BM25, all inside Postgres. This gives fast Korean keyword search.
2. **KURE-v1 + v2:** the best Korean retrieval models right now. Dense vectors in pgvector, multi-vector reranking.
3. **statewave:** Postgres + pgvector, provenance receipts, TypeScript SDK. The closest match to "provenance-strict memory".
4. **SAG:** links entities at query time instead of merging them at ingest, which removes the silent-merge risk. The design ports to Postgres.
5. **Splink:** match weights you can explain, with a Postgres backend. Borderline pairs go to user review, never auto-merged.
6. **GLiNER2 (+ gliner-onnx.js):** cheap CPU extraction before any LLM call, which helps speed.
7. **Absurd or DBOS:** durable, retryable ingestion and replanning using only Postgres.
8. **omi:** a working Flutter app that turns captures into action items and memories (MIT).
9. **Reflexio:** turns user corrections into per-user playbooks; this maps to Luffi's feedback loop.
10. **atomicmemory:** TypeScript + Postgres memory that handles corrections. Pair it with the design ideas from memoweft and wend-core.
