# 01. LLM 메모리·진화형 지식 그래프 프레임워크

> 조사일: 2026-09-28 · 원문: [`sources/01_memory-frameworks_2026-09-28.md`](sources/01_memory-frameworks_2026-09-28.md)
> 성격: 연구 자료 요약입니다. 작업 지시가 아닙니다.

## 결론

어떤 프레임워크도 커널 규칙(같은 이름 자동 병합 금지, 언급 → 신원 결정 분리)을 그대로 지키지 못합니다. **모두 어떤 형태로든 엔티티를 자동 병합합니다.** 채택한다면 커널 옆의 **파생 층**으로만 쓰고, 기준 데이터로 쓰면 안 됩니다.

## 후보

| 순위 | 프로젝트 | 그래프가 스스로 바뀌나 | 스택 적합성 | 자동 병합 | 판단 |
|---|---|---|---|---|---|
| 1 | **Hindsight** (MIT, 3.8만★) | 사실을 "관찰"로 묶고 근거 수로 강화·약화, 모순은 이력으로 | **Postgres + pgvector만** 사용, Node 클라이언트. 서버는 Python | 이름 유사도 + 동시 출현으로 병합. 완전히 끌 수 있는지 미확인 | 실험 1순위. 1.0 전, 한 회사 주도 |
| 2 | **Graphiti** (Zep, Apache) | 이중 시간 축, 모순 시 무효 처리 | Neo4j·FalkorDB·Neptune, Python만 | LLM 병합. 우회는 ID를 직접 넣는 `add_triplet`뿐 | 설계 참고용 |
| 3 | **Cognee** (Apache) | `improve`로 피드백 가중치 증감 | Python. Postgres 그래프는 유료 | 이름 해시로 ID 생성 → 같은 이름 병합 | 피드백 방식만 참고 |
| 4 | **MemOS 2.0** (Apache) | 자연어 정정 API, 백그라운드 재정리, 버전 보관 | 일반 Postgres 그래프 옵션 | 재정리기가 병합(끌 수 있음) | 짧게 실험 가능. 무거움 |
| 5 | **LightRAG** (MIT) | 약함(추가·삭제만) | Postgres + AGE | 이름이 키 | 문서 검색용. 개인 기억용 아님 |

## 걸러낸 것

- **Mem0:** 오픈소스 v3에서 그래프 메모리 제거(유료 전용), 추가만 가능
- **Letta:** 에이전트 도구로 전환, 지식 그래프 아님
- **MS GraphRAG:** 유지보수 모드
- **HippoRAG·A-MEM:** 연구 코드
- **OpenViking·Honcho:** AGPL
- **Supermemory:** 자체 호스팅 엔진 소스 없음

## 읽어 볼 것

**LongMemory**(구 OpenMemory, Apache, TypeScript)는 철학이 커널과 가장 가깝습니다. 기억은 바꾸지 않고 쌓고, 출처가 있고, 기록 시각과 유효 시각을 분리하고, 조심스럽게 병합하고, 망각과 강화가 있습니다. 다만 SQLite 전용이고 사실상 1인 유지보수입니다.
