## 무엇을 조사했나

**"맥락에 따라 계속 스스로 연결되고, 빠르게 쌓이는 세컨드 브레인"**을 만드는 데 쓸 수 있는 최신 기술·오픈소스·사례를 찾았습니다. 해외 커뮤니티(X·Threads, Reddit, Hacker News), GitHub, 컨퍼런스 발표, 논문, 제품을 중심으로 봤습니다.

## 요약

→ 자세한 종합은 [`CONSENSUS.md`](CONSENSUS.md)

1. **통째로 가져다 쓸 오픈소스는 없습니다.** 조사한 메모리 엔진은 느리거나(Graphiti 캡처 1건 10~65초, Zep 저장 후 조회까지 중간값 162초) 이름이 같으면 대상을 합쳐 버립니다.
2. **업계가 하나의 설계로 모이고 있습니다.**
   - 저장할 때는 LLM 없이 빠르게 원본을 쌓는다
   - 사실은 출처가 있는 "주장"으로 두고 지우지 말고 무효 처리한다
   - 이름이 같다고 합치지 않는다
   - 정리는 백그라운드에서 변경안으로 만든다
   - 검색은 키워드와 벡터를 섞고 작은 프로필을 항상 불러 둔다
   - 피드백은 가중치로 반영한다
3. **먼저 제안하기는 아직 누구도 잘 못합니다.** 최고 모델도 타이밍 정밀도가 약 60%입니다. 캡처 앱은 저장만 하고, 먼저 알려 주는 비서는 거의 안 뜨거나 틀리게 뜹니다. "저장한 의도 + 장소·시간 트리거"를 합친 제품은 없습니다.
4. **속도:** 추론 끄기, 짧은 출력, 가벼운 모델, 기기 OCR 힌트로 캡처 → 기억 **2~3초, 캡처당 약 $0.001**이 가능해 보입니다(측정 필요).
5. **직접 경쟁:** Pool(iOS 스크린샷 기억, $2M), Outernet(저장물 → 계획, 월 $6.99). 한 번 제안하기는 Pixel·갤럭시·Siri·카카오가 흡수 중입니다.
