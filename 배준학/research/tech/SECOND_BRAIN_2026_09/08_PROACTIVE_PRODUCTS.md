# 08. 캡처 → 행동 제품과 먼저 제안하기

## 제품 분석

| 제품 | 먼저 하는 것 | 사용자 반응 |
|---|---|---|
| **Pixel Screenshots** | 캡처 시 알림·일정 제안, 저장한 식당을 지도에서 다시 보여 줌 | 검색은 좋지만 가격·날짜를 **지어냄**. 1,800장 중 300장만 처리 |
| **Magic Cue → Gemini Proactive Assistance** | 화면·알림·메일·일정을 읽고 먼저 칩 제안 | 한 달간 일상에서 거의 안 뜸, 지난 항공편을 보여 줌. 약 4개월 만에 첫 유용한 제안 |
| **갤럭시 Now Brief / Now Nudge** | 기기 안 개인 데이터 엔진, 사진·일정 충돌 알림 | Daily Hub는 "쓸데없는 채우기", Now Brief는 정확도 낮음 |
| **iOS 26 Visual Intelligence** | 없음(사용자가 한 번 탭) | 일정 추가는 "실패를 못 봤다". App Intents로 서드파티 연결 가능 |
| **Nothing Essential Space** | 캡처 + 음성 메모 → 할 일 자동 생성 | **"그 할 일을 하라고 알려 주는 걸 자주 잊는다"**, 결국 사용 중단 |
| **Microsoft Recall** | 없음 | 검색은 잘 됨, 행동 제안(Click to Do)은 설익음 |
| **Mem Agent** | 일정에 맞춰 후속 조치("바쁠 땐 기다렸다가 다음 날 아침 초안") | 반응 자료 없음 |
| **Sorti / Fabric / Recall.it** | 요약·주간 정리·복습 일정만 | 정리는 호평, 장소·시간 기반 할 일 제안은 없음 |
| **ChatGPT Pulse** | 밤새 조사 → 하루 5~10장 카드 → "오늘은 여기까지" | **6/17 종료**, 사용자가 관리하는 예약 작업으로 흡수 |
| **Meta AI Studio 봇** | 14일 안에 5개 이상 메시지를 보낸 사용자에게만, 답이 없으면 한 번만 후속 | **상한 설계의 좋은 본보기** |
| **카카오 카나나(카톡 안)** | 기기 안 모델이 대화 맥락을 읽고 먼저 일정 브리핑·장소 제안 | 초기 단계. 독립 앱은 카톡 안으로 흡수 |
| **네이버 쇼핑 에이전트** | 찜·장바구니·위치·희망 배송일로 먼저 대화 | 3월 대비 월 사용자·대화 5배, 일 거래 4배 |

**공통 실패 패턴이 분명합니다.**
- 캡처 앱은 저장만 하고 행동으로 잇지 못합니다.
- 먼저 제안하는 비서는 거의 안 뜨거나 틀리게 뜹니다.
- **"저장한 의도의 그래프 + 장소·시간 트리거"를 합친 제품은 없습니다.** Luffi가 파고들 자리입니다.

## 가져올 오픈소스

- **thunlp/ProactiveAgent** (Apache): 수락·거절·무시 라벨로 "제안할지"를 판정하는 보상 모델(F1 0.918). 라벨 체계와 게이트 발상을 차용합니다.
- **LangChain agent-inbox**: 알림(마감) / 질문(저장 목적) / 검토(보드 재계획) 세 패턴
- **Mem0 proactive 패턴**: 기억을 꺼낼지 예/아니오 분류기 → "의미 있는 맥락 변화 한 번에 하나"
- PRPF, ContextAgent: 싼 게이트 모델을 먼저 돌리고, 통과할 때만 비싼 추론 → 잘못된 트리거를 줄임
- **평가 데이터:** Duolingo 알림 2억 건, ProAgentBench 이벤트 2.8만 건

## 제안 설계 (출발값)

### 저장 목적 추론
- **범주:** 요리 / 방문 / 구매 / 비교 / 선물 / 일정·마감 / 참고 / 영감
- **신호:**
  - 이미지 텍스트(가격·날짜·주소·재료·영업시간)
  - 출처 앱
  - 사용자의 짧은 메모
  - **10분 안에 같은 대상 3장 이상**(비교·구매 신호)
  - 같은 장소 반복 저장
  - 진행 중인 보드·일정과의 연결(제주 일정 + 제주 식당 캡처 → 여행 준비)
  - 과거에 이 범주로 실제 행동했는지
- **언제 물을지**(Horvitz의 실행/질문/무행동 모형)
  - 최상위 목적 확률 **0.75 이상** → 조용히 정하고 고칠 수 있는 칩으로 표시
  - **0.45~0.75**이고 후보마다 행동이 다르면 → 버튼 2~3개 + "그냥 저장"
  - 그 외 → "영감"으로 두고 묻지 않음
  - 불확실성은 목적을 여러 번 샘플링한 엔트로피로 측정(질문을 10%에만 써도 효과가 두 배, arXiv 2311.09469)
- **질문 방식:** 푸시가 아니라 앱 안 "정리" 카드, 하루 약 3개 이하
- **신뢰:** 이미지 텍스트에 없는 가격·날짜는 절대 보여 주지 않고, 원본 조각을 옆에 표시(Pixel Screenshots의 교훈)

### 언제 제안할지
- **장소:** 실제로 가는 마트와 자주 저장한 장소에 지오펜스. **3~5분 머무를 때만**(지나가기만 하면 무시), 반경 100~150m 이상
- **마감:** 쿠폰·행사·팝업 종료 이틀 전과 당일, 평소 앱을 여는 시간대
- **일상 패턴:** 앱을 연 기록과 과거 수락에서 학습(예: 토요일 10시 식단 계획)
- **조건 변경:** 보드는 조용히 다시 계획하고, **사용자가 약속한 일이 깨질 때만 푸시**
- **점수:** P(수락 | 사용자, 목적, 트리거, 맥락) × (긴급도 + 빠진 항목의 가치) − 방해 비용. 싼 점수는 기기에서 계산하고, 통과할 때만 LLM이 문구를 씁니다.
- **전달:** 기대 수락률이 약 15~20%를 넘는 것만 푸시하고, 나머지는 앱 안 카드·위젯으로
- **상한:** **하루 1회, 주 4회.** 같은 종류를 두 번 연속 무시하면 멈춤. 하루 목록은 "오늘은 여기까지"로 끝
- **순간:** 잠금 해제·앱 열기 같은 **자연스러운 틈**에
  - 흐름의 경계에서 제안하면 참여 52%, 한창 작업 중이면 62%가 무시(IUI'26)
  - 활동의 틈에 전달하면 반응 시간이 54 → 27분으로 절반(약 68만 명)
  - 최고 모델도 타이밍 정밀도 약 61% → **게이트 필수**

### 수락·거절에서 배우기
- **라벨**
  - 수락 = 1: 탭 + 실제 행동(지도 열기, 재료 체크, 보드 추가)
  - "관심 없음" = 0 (가중치 1)
  - 스와이프 닫기 = 0 (가중치 0.5)
  - 무시·만료 = 0 (가중치 0.25)
  - "목적이 틀림"은 타이밍 모델이 아니라 목적 분류기를 다시 학습
  - 미루기는 시간대를 이동
- **성공 창:** 2시간 이내, 장소 트리거는 방문 중
- **모델**
  - (사용자 × 목적 × 트리거)별 Beta 점수. 전체 평균으로 시작하고 초기 강도는 약 10
  - **"아무것도 안 보내기"를 포함한** Thompson sampling
  - 같은 문구 반복 벌점(Duolingo, 반감기 15일)
  - 라벨이 약 50개 쌓이면 맥락 밴딧(시각, 요일, 거리, 저장 후 경과일, 마감, 범주)
- **추적 지표:** 수락률, 제안 빈도, 범주 끄기·알림 끄기 비율

## iOS·Android 제약

| | iOS | Android |
|---|---|---|
| 새 스크린샷 감지 | **백그라운드 훅 없음.** 앱을 열 때 `PHPersistentChangeToken`으로 따라잡기(전체 사진 권한 필요). 공유 확장이 가장 확실. 단축어 스크린샷 트리거·Back Tap은 **검증 필요** | MediaStore 변경에 반응하는 작업(JobScheduler/WorkManager). 콜백마다 재등록, 재부팅 후 재등록 필요 |
| 권한 | 제한 접근이면 선택한 사진만 보임 | `READ_MEDIA_IMAGES`는 Play 정책상 **핵심 기능 입증** 필요. 사진 선택기·공유 시트 대안 필수 |
| 백그라운드 실행 | 앱 새로고침 약 30초, 실행 시점은 시스템이 결정 | 대기 버킷별 할당(활성 시간당 20분 ~ 드묾 하루 10분). Android 16에서 더 엄격 |
| 지오펜스 | **앱당 20개**. 가장 가까운 약 19곳 + 재중심용 큰 영역 1개로 우회 | **앱당 100개**, 반경 100~150m 이상, 지연 2~6분, 백그라운드 위치 권한 |
| 기기 AI | Foundation Models에 이미지 입력·OCR 도구 추가(WWDC26) | Gemini Nano Prompt API(베타) — ML Kit OCR을 먼저 돌리라고 권장 |
