# 업계가 수렴한 원칙 (2026년 9월 기준)

> 작성: 배준학 (Claude Code 보조) · 2026-09-29
> 근거: 이 폴더의 조사 01~10을 가로질러 종합. 각 원칙 옆 괄호가 근거 문서 번호입니다.
> 성격: 연구 자료입니다. 작업 지시가 아닙니다.

## 한 줄 결론

"맥락에 따라 계속 스스로 연결되는 세컨드 브레인"을 **통째로 해 주는 오픈소스는 없습니다.** 조사한 엔진은 느리거나(Graphiti 캡처 1건 10~65초, Zep 저장 후 조회까지 중간값 162초), 이름이 같으면 대상을 합쳐 버립니다.

대신 X·Reddit·HN·컨퍼런스·논문에서 **같은 설계로 수렴하는 흐름**이 뚜렷합니다.

## 6가지 원칙

### 1. 저장할 때는 LLM을 부르지 않는다 (04, 05, 07)
- 원본은 수정 없이 즉시 쌓습니다(append). 해석·연결·요약은 비동기로 처리합니다.
- 근거
  - Engram(arXiv 2606.09900): 빠른 쓰기 경로, 비동기 이중 시간(bi-temporal) 그래프. 전체 맥락보다 토큰을 8배 적게 쓰고 LongMemEval 83.6%
  - Activity Frames: 하루치 화면 활동을 68ms에 결정적으로 정리
- 반례
  - Zep: 사실을 저장한 뒤 조회되기까지 중간값 162.7초
  - Graphiti: 에피소드당 10~65초
  - LangMem: p95 60초

### 2. 사실은 "주장"으로 저장하고, 지우지 말고 무효 처리한다 (05, 07, 02)
- 모든 사실에 출처, 유효 시작·종료, 상태(현재·대체됨·충돌·철회), 대체 포인터를 둡니다.
- Zep CTO 발표 "Citation Needed": 병합돼도 출처 링크 유지, 모순이면 옛 엣지를 날짜와 함께 무효 처리, 삭제는 남은 출처가 없을 때만.
- Reddit: "요약기가 '페이지에 X라고 써 있었다'를 '사실 X'로 세탁한다." → SNS 캡처는 **제3자의 주장**으로 저장해야 합니다.
- 반복 ≠ 진실: 거짓을 세 번 반복하면 100% 진실을 이겼다는 실험이 있습니다. Mem0는 정정한 값이 옛 값으로 47% 되살아났습니다.

### 3. 이름이 같다고 합치지 않는다 (05, 07, 06)
- **확실한 키**(주소, 전화번호, 장소 ID)가 있을 때만 합칩니다.
- 애매하면 "같을 수도 있음" 엣지로 두고 사용자나 백그라운드 작업이 판단합니다.
- 기준 예: 유사도 0.95 이상 제안 / 0.85~0.95 검토 / 그 아래는 새 노드 (Iusztin, HN)
- 현업의 말: "잘못 합친 걸 되돌리는 게 제일 고통스럽다", "Apple(과일)이 Apple Inc.와 합쳐졌다"
- 도구: Splink(설명 가능한 매칭 점수), Bosun(0.6B 엣지 검증 모델)

### 4. 정리는 백그라운드에서 하고, 변경안을 보여 준 뒤 적용한다 (04, 07, 02)
- 대형 서비스가 모두 이 방식("dreaming")을 내놨습니다.
  - OpenAI ChatGPT Dreaming (6월)
  - Anthropic Managed Agents dreaming (5월): 변경 전 검토 옵션
  - OpenClaw Dreaming: DREAMS.md 일기
  - GBrain: 밤마다 정리
- 이제 정리 자체는 차별점이 아닙니다. **사용자가 변경을 보고 되돌릴 수 있느냐**가 차별점입니다. OpenAI는 메모리 요약을 고쳐도 실제 기억에 반영되지 않는다고 비판받았습니다.

### 5. 검색은 키워드와 벡터를 섞고, 작은 프로필은 항상 불러 둔다 (04, 05, 07)
- 공정 비교 순위표 AML: 단순한 **SQLite 전문 검색 기준선(41.79)이 Mem0(42.07)와 비슷**했습니다.
- LoCoMo recall@20: BM25+벡터 RRF 0.609, BM25 0.552, 벡터 0.526, 최근 N개 0.024
- MemAware: 질문할 때마다 검색만 하면 은연중에 기억해 내야 하는 문제에서 0.7%로, **기억이 없는 것과 같았습니다.** 약 3천 토큰짜리 주제 색인을 항상 불러 두면 17.3%였습니다.
- 에이전트가 기억을 아예 조회하지 않는 실패가 많습니다(61%). → **코드가 맥락을 강제로 넣어야** 합니다.

### 6. 피드백은 규칙 문장이 아니라 가중치·장치로 반영한다 (02, 07, 08)
- 수정 237건을 규칙 문장으로 넘겨도 새 에이전트가 같은 범주에서 13번 틀렸습니다(Calx, HN).
- 기억을 "유사도 × 과거 유용성"으로 순위 매기기, 엣지별 Beta 점수, 무시·거절을 가중치로 반영합니다.
- 스스로 절차를 고쳐 쓰는 방식은 위험합니다. 진화시킨 21개 구성 전부 안전하지 않은 산출물을 냈습니다(arXiv 2608.12851). **기억과 상태만 갱신하고 절차는 사람이 관리**합니다.

## 시장에서 보이는 것 (04, 08)

- **화면을 보고 한 번 제안하기는 대기업이 흡수 중:** Pixel Screenshots, Gemini Proactive Assistance(Magic Cue 후속), 갤럭시 Now Nudge, Siri, 카카오 카나나
- **실패 패턴 두 가지**
  - 캡처 앱은 저장만 하고 행동으로 잇지 못함(Nothing Essential Space, Pixel Screenshots)
  - 먼저 알려 주는 비서는 거의 안 뜨거나 틀리게 뜸(Magic Cue, Now Brief)
- **먼저 제안의 성적:** ChatGPT Pulse는 종료됐고, 대화 안에 있던 Poke는 인수됐습니다.
- **직접 경쟁:** Pool(iOS 스크린샷 기억, $2M), Outernet(저장물 → 계획, 월 $6.99, 1.8만 명), Stash, Sift
- **Luffi의 자리:** 여러 캡처에 걸친 "저장한 의도 → 할 일 → 다시 계획". Reddit의 한 문장이 핵심입니다. "AI 요약은 글이 무슨 내용인지는 기억하지만, 내가 그걸로 뭘 하려 했는지는 기억하지 못한다."
