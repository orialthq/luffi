# 02. 피드백 루프·자기 진화 메모리 연구

> 조사일: 2026-09-28 · 원문: [`sources/02_feedback-loop-research_2026-09-28.md`](sources/02_feedback-loop-research_2026-09-28.md)
> 성격: 연구 자료 요약입니다. 작업 지시가 아닙니다.

## 메커니즘별 정리

| 계열 | 대표 | 방식 | 판단 |
|---|---|---|---|
| 링크·구조 변화 | **A-MEM** | 새 노트가 들어오면 LLM이 이웃 노트의 키워드·태그를 **제자리에서 고쳐 씀** | 조용한 수정이라 부적합. 독립 재현 점수도 낮음 |
| | **All-Mem** (2026-03) | 오프라인 진단기가 분할·병합·갱신을 **신뢰도와 함께 제안**, 원본 근거는 불변 | 채택할 만한 패턴 |
| | HippoRAG 2 | 동의어 엣지 + 개인화 PageRank, 무효 처리 없음 | GraphRAG-Bench 1위이나 개인 기억용 아님 |
| 시간에 따른 충돌 | **Graphiti** | 모순 엣지에 `invalid_at` 표시, 에피소드 단위 출처 | 설계 참고. LLM 자동 병합이 문제 |
| | TEPA (2026-08, 코드 없음) | 가설 → 활성 → 철회, 관측 5회 후 Beta 점수 0.3 미만이면 보관 | 점수 규칙 참고 |
| | Eywa · SodaMem | 근거 먼저 저장, 사실에 원문 구간, 충돌은 SUPERSEDES/CONTRADICTS 엣지 | 출처 보존 설계의 참고 모델 |
| 백그라운드 정리 | Letta sleep-time, Mastra 관찰 메모리, RecMem | 쉬는 시간에 기억 재구성. 비슷한 상호작용이 반복될 때만 추출(토큰 87% 절감 주장) | 반복될 때 정리 → 비용 통제 |
| 강화학습 관리자 | Memory-R1, Mem-α | 추가·갱신·삭제를 보상으로 학습 | QA 보상이 필요하고 코드가 멈춤. 나중에 |
| 맥락 진화 | **ACE** (ICLR'26) | 생성 → 반성 → 큐레이터가 "도움/해로움" 카운터가 달린 항목을 추가 | 사용자별 플레이북에 적용 가능 |
| | Cognee 피드백 | 1~5점 평가를 답에 쓰인 노드·엣지 가중치에 반영 | 데모에선 가중치가 시각화에만 쓰였다는 점은 미확인 |
| 먼저 제안 | ProAgentBench | 그래프 메모리가 타이밍 정확도를 11.8% 올림. 최고 모델도 타이밍 64% | 게이트가 필요 |

## 채택 권고

1. **근거 먼저, 덮어쓰지 않는 사실 저장소.** 모순이면 `invalid_at` + SUPERSEDES 엣지. 자동 병합 대신 `MERGE_CANDIDATE` 엣지.
2. **제안만 하는 백그라운드 작업.** 밤마다 또는 비슷한 캡처가 반복될 때 신뢰도가 붙은 `suggested_link`를 생성하고, 사용자가 수락해야 반영.
3. **결과로 움직이는 엣지 가중치.** 수락·수정·실행·무시 → Beta 점수, 낮으면 보관(삭제 아님).
4. **사용자별 ACE식 플레이북.** 어떤 제안을 받아들이는지를 카운터가 달린 항목으로 기록.
