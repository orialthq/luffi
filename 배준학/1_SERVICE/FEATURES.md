# 구현할 기능

> 근거: 사업계획서, 모두의 창업 지원서, 펀딩 소개 스토리 v64, 구조도(Fig.01 Capture Purpose, Fig.02 Context Updates)
> 서비스 개요는 [`README.md`](README.md)에 있습니다. 이 문서는 발표에서 약속한 기능을 **구현 단위로** 정리한 것입니다.

## 전체 흐름

```
캡처 ─▶ F1 수집 ─▶ F2 추출 ─▶ F3 기억 연결 ─▶ F4 저장 목적 파악
                                                    │
                  F5 활동 제안 ◀──────────────────────┘   (또는 사용자가 목적 직접 입력)
                        │ 사용자 수락
                        ▼
                  F6 TaskBoard ─▶ F7 진행 반영·다시 계획 ─▶ F8 시간·장소 알림
                        └──────────── 선택·수정·완료가 F3 기억으로 돌아감 ───────────┘
```

## 기능 목록

| ID | 기능 | 해야 하는 일 | 발표 속 예시 | MVP |
|---|---|---|---|---|
| **F1** | 캡처 수집 | 초기 설정 뒤에는 **캡처만 하면** 들어온다. 공유 시트·사진 선택, 가능하면 앱을 열지 않아도 백그라운드로. 원본 보존 | "캡처 한 번이면, 알아서 기억에 담겨요" | ✓ |
| **F2** | 정보 추출 | 이미지에서 장소·제품·방법·가격·재료 등을 추출하고 원본 위치와 연결 | 다낭 맛집 → 메뉴·매장·위치 | ✓ |
| **F3** | 기억 연결 (Second Brain) | 추출한 정보를 기존 정보와 **관심사·목적·선택·진행 상태**에 그래프로 연결. 초기 설문과 이후 행동으로 계속 갱신 | 다낭 맛집 캡처 ↔ 기존 숙소·일정 | ✓ |
| **F4** | 저장 목적 파악 | 캡처의 저장 목적 후보를 추론. **뚜렷하면 묻지 않고**, 불분명하면 한 번 확인(후보 선택 / 직접 입력 / 아직 안 정함) | "이 맛집 정보를 어떤 목적으로 캡처했나요?" (Fig.01) | ✓ |
| **F5** | 활동 제안 | 저장 정보와 맥락으로 지금 필요한 활동을 **먼저 제안**. 사용자가 목적을 직접 입력할 수도 있음 | "요즘 다이어트 중이시죠? 이 덮밥 어때요?" / "나 내일 코스트코 가는데 레퍼런스 쭉 뽑아줘" | ✓ |
| **F6** | TaskBoard 구성 | 수락한 활동에 맞춰 관련 자료(Reference)를 고르고 할 일(To-do)과 실행 순서를 구성. 할 일마다 자료 연결, 비교·선택·일정 배치 | 다이어트 덮밥: 재료 확인 → 장보기 → 요리 | ✓ |
| **F7** | 진행 반영·다시 계획 | 체크·완료·메모·조건 변경을 기억과 보드에 반영하고, 남은 할 일과 자료를 갱신 | 두부·버섯 없음 → 장보기 목록 갱신 / 예산이 바뀌어 보류했던 식당 재제안 (Fig.02) | ✓ |
| **F8** | 시간·장소 알림 | 필요한 시간·장소에서 남은 할 일과 자료로 안내 | 18:30 마트 근처 장보기 알림, 22:00 스트레칭 알림 | ✓ |
| **F9** | 그래프 시각화 | 정보 간 연결을 그래프로 보여 주며 관심사·저장 기록 탐색 | 정리함 그래프 | 이후 |
| **F10** | 공유 카드 | 정리한 정보를 카카오톡 등으로 전달 | 맛집 카드 공유 | 이후 |
| **F11** | 공동 TaskBoard | 친구와 자료를 모아 후보 비교, 할 일·역할·진행 공동 관리 | "우리의 토요일" | 이후 |
| **F12** | 공개 보드 재사용 | 다른 사람의 공개 보드를 내 조건에 맞게 재구성, 경험 재공유 | 민지의 연남동 맛집 → 내 보드로 | 이후 |
| **F13** | 과금 | 크레딧 차감(캡처 분석·계획 생성·갱신), 충전, 구독. 보드 열람·To-do 체크는 무료 | 100크레딧 무료 제공 | 7~12개월 |

## 지켜야 할 원칙

- **사용자가 할 일은 캡처뿐이다.** 별도 입력·태그·설명을 요구하지 않는다.
- **확인은 필요할 때만 한다.** 목적이 불분명하거나, 계획을 확정할 때만 묻는다.
- **제안은 사용자 확인 후 보드가 된다.** 의도 추론 → 사용자 확인 → TaskBoard.
- **실행 결과는 다시 기억이 된다.** 선택·수정·완료가 다음 제안과 계획의 기준이 된다.
- **자주 알리지 않는다.** 필요한 순간에만. 멘토링 과제에도 "얼마나 자주 알릴지"가 포함돼 있다.

## 측정할 것 (사업계획서 KPI)

| 구분 | 지표 |
|---|---|
| 제품 효과 | 추가 입력·설정 횟수, 준비 시간, 변경 반영 정확도, 제안 수정량, 재사용률 |
| 기술 품질 | 정보 추출 정확도, 맥락 연결·제안의 적합성, 보드 반영 정확도, 응답 속도, 처리 비용 |
| 사업 | 채널별 고객 확보 비용, 첫 보드 사용률, 공유를 통한 유입, 유료 전환율, 충전 재구매율, 구독 유지율 |
