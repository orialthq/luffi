# Luffi는 무엇인가

> 사업계획서·모두의 창업 지원서·발표 자료를 한 장으로 줄였습니다.

## 한 줄로

**저장해 둔 정보를 내 상황에 맞게 연결해서, 필요한 일을 먼저 제안하고 끝까지 돕는 모바일 AI.**
"캡처를, 다음 행동으로."

## 풀려는 문제

- SNS에서 맛집·레시피·뷰티 팁을 캡처해 두지만, 막상 필요할 때 다시 꺼내 쓰지 않는다.
- 하고 싶은 일을 정해도, 자료를 비교하고 할 일과 순서를 짜는 건 결국 내 몫이다.

## 어떻게 동작하나

```
캡처 → ① 기억(Second Brain) → ② 제안·계획 → ③ 할 일 보드(TaskBoard)
          ↑                                        │
          └──────── 선택·수정·완료가 다시 기억으로 ──────┘
```

- **① 기억:** 캡처만 하면 가게·제품·방법을 뽑아서, 내 관심사·목적·진행 상황과 연결해 둔다.
- **② 제안·계획:** 왜 저장했는지 짐작하고(애매하면 한 번만 묻고), 지금 필요한 일을 먼저 제안한다. 내가 목적을 직접 말해도 된다.
- **③ 할 일 보드:** 할 일마다 필요한 자료를 붙여 주고, 체크하고 완료할 때마다 다음 할 일을 갱신한다. 필요한 시간·장소에서 알려 준다.

**발표 속 예:** 저녁 6시 "요즘 다이어트 중이시죠? 이 덮밥 어때요?" → 냉장고 재료 체크 → 두부·버섯만 장보기 목록에 → 마트 근처에서 알림 → 요리 완료가 다시 기억으로

## 지킬 것

- 사용자가 할 일은 **캡처뿐**이다. 따로 입력하거나 태그를 달지 않는다.
- **확인은 필요할 때만** 묻는다.
- 선택·수정·완료는 **다음 제안의 기준**이 된다.
- **자주 알리지 않는다.**

## 사업

- **초기 분야:** 맛집·뷰티·패션
- **돈 버는 방법:** 가입 시 100크레딧 무료 → 충전(100크레딧 $0.50) → 구독(월 $5) → 구매·예약 제휴 수수료
- **일정:** 6개월 안에 MVP 출시, 이후 유료화 → 공유·SNS → 확장
- **역할:** 준학 = AI(추출·기억·목적 추론·제안), 동희 = 서비스(백엔드·인프라·배포·사용자 검증), 앱과 보드는 함께
