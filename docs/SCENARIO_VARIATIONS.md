# 이미지 기반 시나리오 변형 검증

이 검증은 합성 캡처를 실제 `/v1/analyze` API에 보내 받은 응답을 보존하고, 그 응답을 테스트에서 재생한다. 합성 화면은 실제 매장·상품·건강 효과를 증명하지 않는다. 이미지와 응답은 `server/test/fixtures/variation_*`에 있고, `server/test/scenario_variations.test.js`가 이미지 SHA-256, 분석 스키마, 필드 근거, 보드 생성, 사용자 확정, 지식 그래프 연결과 삭제를 확인한다.

| 사례 | 분석 응답에서 확인된 정보 | 보드·그래프에서 지켜야 할 경계 |
| --- | --- | --- |
| 두부 달걀 볶음 + 두부 상품 | 두부 `300g`, 달걀 `2개`, 소금 `약간`; 상품 `2,400원` | 사용자가 소금을 `as_needed`로 확정한다. 4인분 환산 때 숫자를 만들지 않는다. 두 보드의 확정 결과를 연결하되 구매 사실은 만들지 않는다. |
| 이전 가격 + 현재 표시 가격 | `19,900원` 이전 표시가와 `12,900원` 화면 표시가가 각각 추출됨 | 사용자 확인 전에는 쇼핑 후보로 받지 않는다. 사용자가 화면 표시가를 고르면 별도 확인 근거로 연결하고, 이전 표시가는 선택할 수 없게 한다. 할인율·실제 결제액·구매 완료를 추론하지 않는다. |
| 제주 여행 + 성산읍 식당 | 여행 장소와 `제주 바다국수`, `제주 서귀포시 성산읍` | 사용자가 각각 일정과 식당을 확정한 후 `travel_dining`으로 연결한다. 일정과 식당 선택만으로 방문·예약을 만들지 않는다. |
| 패션 + 뷰티 | 기존 재킷·클렌저 이미지의 실제 API 응답 | 코디와 루틴을 별도로 확정하고 연결한다. 연결만으로 착용·제품 사용을 만들지 않는다. |
| 홈트 + 운동 준비 꿀팁 | 기존 홈트 응답과 새 꿀팁 화면의 순서 있는 `steps` 3개 | 생활 꿀팁의 `facts`/`steps` 두 표현을 화면 근거가 있을 때만 후보로 받는다. 연결만으로 운동 수행·꿀팁 실천을 만들지 않는다. |

생활 꿀팁 화면은 첫 실제 분석에서 `facts: []`, `steps: [1,2,3]`으로 나왔다. 기존 구현은 `facts`만 허용해서 이 캡처를 버렸으므로, 가져오기 단계에서 `life_tip.tip` 언급을 만들고 보드 후보는 근거가 붙은 연속 순서의 `steps`도 읽도록 수정했다. 단계의 원본 assertion을 철회하면 대기 중인 계획 승인이 `CONTEXT_STALE`로 실패한다.

기본 테스트는 모델 호출 없이 저장된 실제 응답을 재생한다. `cd server && npm test`로 실행한다. 분석 모델이 바뀌었을 때는 개발 서버를 켠 다음 `npm run test:scenario-variations-live`로 다섯 장의 새 이미지를 다시 분석한다. 새 응답을 검토하고 고정하려면 `npm run test:scenario-variations-live -- --record`를 사용한다. 이 명령은 의미와 근거 검사를 통과한 뒤에만 응답 파일을 갱신한다. 기존 패션·뷰티·여행·운동 이미지는 각 도메인의 `test:*image-live` 명령으로 재확인한다.

현재의 `scenario.connection_*_subject`는 **두 활동의 확인된 결과를 연결**한다. 두부 재료 요구량과 특정 두부 판매 상품이 같은 실물이라는 동일성, 여행 장소와 식당 사이의 거리·이동 시간, 상품 재고나 실시간 가격은 주장하지 않는다. 그런 주장이 필요해지면 별도의 근거·사용자 확인·갱신 규칙을 갖춘 관계로 추가해야 한다. 이전/현재 가격이 함께 보이는 화면은 `ingestion.reviewed_field`로 현재 표시 가격을 사용자가 확인한 뒤 쇼핑 보드 후보가 된다. 확인 근거가 철회·정정되면 그 근거로 만든 계획은 무효화된다.

연결된 쇼핑 보드의 `recipeNeeds`는 레시피의 `calculate_requirements` 결과를 읽기 전용으로 보여준다. 테스트에서는 4인분 환산 결과가 `두부 600g`, `달걀 4개`, `소금 필요한 만큼`으로 표시되고, 빈 재고 관측을 재고 0으로 해석하지 않아 `missingQuantity`는 `unknown`으로 남는다. 재료 근거를 철회하면 목록은 `stale` 상태만 반환하고 수량을 숨긴다.
